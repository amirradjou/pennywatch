pennywatch

An independent performance history of PennyLane, Lightning and Catalyst. The same circuits run on every build, and any change in what they cost gets traced to the pull requests behind it.

    Each row is a change from one build to the next: 0.5% or more in a counted metric with the runs of the two builds apart, or any change in a gate count. Confirmed means a second, separate measurement showed the same change.

    How it works

    • Instructions, not time. Each circuit runs under Valgrind's Cachegrind, single-threaded, in a pinned container, counting only the circuit and not the imports. On a busy machine, wall-clock time moved by a factor of four while the count moved by less than 0.001%.
    • Several memory layouts. The same code on the same machine can cost half a percent more when something shifts its addresses by a few bytes. The Python calls stay the same, so the extra work is inside the interpreter. So each cell runs under several layouts, the figure is their median, and a change only counts if the runs of the two builds are apart.
    • Every run proves itself. Each cell also runs a canary with 1% extra gates, which has to show up, and each circuit's answer has to be right. A build that fails either gets thrown out, not published.
    • The set is what's measured. One Catalyst build pins exact PennyLane and Lightning builds, so one version names a whole stack.

    Limits

    • Instructions aren't time. Cache misses, branch prediction and memory bandwidth don't show up, so this complements real timing and doesn't replace it.
    • Single-threaded and CPU only. OpenMP scaling and GPU devices are out of scope, and AVX-512 kernels aren't measured, because Valgrind can't run them.
    • Small circuits, around 18 qubits. Effects that only appear at scale can't be seen here.
    • Old dev builds may leave TestPyPI, so past results may not stay reproducible.
